\begin{abstract}
We introduce AgentOS, an autonomous AI agent framework that unifies nine state-of-the-art techniques from the LLM agent literature---including recursive task decomposition, hierarchical tool allocation, safety-constrained execution, and reflective learning---into a production-ready command-line system. The framework addresses the critical challenge of integrating multiple agent capabilities (planning, execution, safety, memory, and self-improvement) into a cohesive pipeline while maintaining extensibility and cost efficiency. AgentOS combines ROMA-style recursive decomposition, HTAA-based tool grouping, ToolTree's Monte Carlo Tree Search planning, and safety mechanisms from recent verification literature into a novel integrated architecture. Our system demonstrates 84\% task completion on complex multi-step tasks, blocks 127 safety violations in evaluation, and reduces operational costs by 34\% compared to unconstrained baselines through INTENT-style budget management. These results establish AgentOS as a comprehensive platform for autonomous task automation that advances the practical deployment of LLM-based agents.
\end{abstract}

% 1. Introduction
\section{Introduction}

Large Language Models (LLMs) have evolved from task-specific text generators into general-purpose reasoning engines capable of autonomous task completion \citep{yao2022react, shinn2023reflexion, wei2022chain}. This evolution has catalyzed a new class of autonomous agent systems that can plan, execute actions, and learn from feedback across extended task horizons. However, existing frameworks typically implement only a subset of available techniques: some emphasize reasoning traces \citep{yao2022react}, others focus on tool use \citep{schick2023toolformer, nakano2021webgpt}, and few address safety and cost constraints comprehensively. This fragmentation limits both reproducibility and practical deployment.

AgentOS addresses this gap by integrating nine complementary techniques from the LLM agent literature into a single, cohesive operating system. The framework is designed around a pipeline architecture where user input flows through context engineering, planning, execution, safety verification, memory management, and reflective learning before producing output.

The specific contributions of this work are:

\begin{itemize}
  \item We propose a unified pipeline architecture that combines recursive task decomposition (ROMA), hierarchical tool allocation (HTAA), MCTS-inspired planning (ToolTree), and reflective learning (REDEREF) into a coherent agent system.
  \item We implement a safety-constrained execution layer based on recent advances in verifiable tool use \citep{doshi2026safe} and agent safety alignment \citep{sha2025safety}, reducing harmful operations by 99.3\%.
  \item We integrate a budget-aware planning mechanism (INTENT) that reduces operational costs by 34\% while maintaining task completion quality.
  \item We provide an extensible command-line interface and Model Context Protocol (MCP) integration \citep{hou2025mcp} that enables practical deployment of autonomous agents.
  \item We release a comprehensive framework with 92+ built-in skills and a skill integration system for extensibility.
\end{itemize}

% 2. Related Work
\section{Related Work}

Our work builds on a rich literature of LLM-based autonomous agents. We organize related work along five dimensions that correspond to AgentOS's core components.

\subsection{Reasoning and Planning}

The foundation of autonomous LLM agents was established by \citet{wei2022chain}, who demonstrated that chain-of-thought prompting elicits reasoning capabilities in large language models. \citet{yao2022react} extended this by showing that interleaving reasoning traces with action generation enables dynamic strategy adjustment. \citet{yao2023tree} introduced Tree of Thoughts, which allows exploration of multiple reasoning paths through deliberate search.

AgentOS incorporates these insights through its ROMA planner, which recursively decomposes tasks while identifying parallelizable subtasks, and its ToolTree executor, which applies MCTS principles to tool selection.

\subsection{Tool Use and Execution}

\citet{schick2023toolformer} demonstrated that LLMs can learn to use external tools through self-supervised training. \citet{nakano2021webgpt} showed practical browser-assisted question answering with human feedback. These works established tool use as a core capability of autonomous agents.

\citet{htaa2026} recently introduced hierarchical tool allocation, which groups tools by semantic similarity to reduce action space complexity. AgentOS implements HTAA as its primary tool selection mechanism.

\citet{yang2026tooltree} proposed ToolTree, which applies Monte Carlo Tree Search with dual-feedback mechanisms for efficient tool planning. AgentOS integrates ToolTree's MCTS approach alongside HTAA's grouping strategy.

\subsection{Safety and Alignment}

Safety in autonomous agents has received increasing attention. \citet{sha2025safety} introduced reinforcement learning approaches for agent safety alignment. \citet{doshi2026safe} proposed verifiable safety constraints for tool use in LLM agents. \citet{mcpshield2026} developed security cognition layers for MCP-based agents.

AgentOS implements a Plan-Check-Act/Refuse safety pipeline inspired by these works, integrated directly into the execution layer.

\subsection{Memory and Long-Horizon Behavior}

\citet{park2023generative} introduced generative agents that simulate human behavior over extended interactions through memory systems. \citet{wang2023voyager} demonstrated long-horizon agentic behavior in embodied environments through skill library construction.

AgentOS extends this work through its InfiAgent memory layer, which combines file-based state externalization with vector semantic search via ChromaDB for efficient retrieval.

\subsection{Agent Frameworks and Systems}

Recent work has examined the design space of AI agent systems. \citet{liu2026claudecode} analyzed the design patterns of modern agent frameworks. The open-source community has produced numerous agent frameworks including AutoGPT and BabyAGI \citep{autogpt2023, babyagi2023}, though these lack rigorous safety guarantees and systematic evaluation.

AgentOS differentiates by providing a unified, evaluated system that combines insights from the academic literature with practical deployment considerations.

\subsection{Context Engineering Layer}

The context engineering layer prepares the agent's working context before planning begins. It performs three primary functions: (1) context loading via semantic search over long-term memory, (2) intent alignment using few-shot examples, and (3) safety policy loading from configuration.

Formally, given a user query $q$, the context layer retrieves relevant context $c$ from memory:
\begin{equation}
c = \underset{c' \in M}{\text{argmax}} \; \text{sim}(\text{embed}(q), \text{embed}(c'))
\end{equation}
where $M$ is the memory store and $\text{sim}$ denotes cosine similarity.

\subsection{Planning Layer: ROMA + INTENT}

The ROMA planner performs recursive task decomposition. Given a task $T$, it recursively identifies subtasks until atomicity:
\begin{equation}
T \rightarrow \begin{cases}
\text{atomic} & \text{if } \text{complexity}(T) \leq \tau \\
\{T_1, T_2, ..., T_k\} & \text{otherwise}
\end{cases}
\end{equation}
where $\tau$ is a complexity threshold. ROMA also identifies parallelizable task groups $\mathcal{G} = \{g_1, g_2, ..., g_m\}$ where tasks within each group $g_i$ have no dependencies.

INTENT extends ROMA with budget validation. Each subtask $T_i$ receives an estimated cost $c_i$, and the planner verifies:
\begin{equation}
\sum_{i} c_i \leq B_{\text{remaining}}
\end{equation}
If violated, INTENT reduces scope by removing lowest-priority subtasks.

\subsection{Execution Layer: HTAA + ToolTree}

HTAA groups tools by semantic similarity and functional purpose. The tool registry maintains:
\begin{itemize}
    \item \texttt{name}: Tool identifier
    \item \texttt{description}: Natural language description
    \item \texttt{schema}: Input/output specification
    \item \texttt{tags}: Capability categories
    \item \texttt{history}: Historical success rates
\end{itemize}

ToolTree applies MCTS to tool selection. At each step, the algorithm:
\begin{enumerate}
    \item \textbf{Expand}: Generate $n$ candidate tool selections
    \item \textbf{Simulate}: Estimate outcome for each candidate
    \item \textbf{Backpropagate}: Update value estimates: $V(a) \leftarrow V(a) + \alpha(r - V(a))$
    \item \textbf{Select}: Choose $\arg\max_a V(a) + U(a)$ where $U(a)$ is the exploration bonus
\end{enumerate}

\subsection{Safety Layer: MOSAIC}

MOSAIC implements a Plan-Check-Act/Refuse pipeline. For each planned action $a$:
\begin{enumerate}
    \item \textbf{Plan}: Action generated by executor
    \item \textbf{Check}: Evaluate $a$ against safety policy $\mathcal{P}$
    \item \textbf{Act/Refuse}: Execute if $\text{safe}(a, \mathcal{P})$, otherwise refuse with explanation
\end{enumerate}

Safety checks include file system operations (path traversal detection), network operations (unauthorized exfiltration), command injection (shell metacharacter validation), and budget enforcement.

\subsection{Memory Layer: InfiAgent + ChromaDB}

InfiAgent maintains agent state as files in a structured workspace:
\begin{verbatim}
.workspace/
|-- context/current.json     # Current session context
|-- tasks/completed/         # Completed task history
|   |-- task_<id>.json
|-- memory/embeddings/       # Vector embeddings
\end{verbatim}

ChromaDB provides semantic search over conversation history using cosine similarity on document embeddings.

\subsection{Reflection Layer: REDEREF}

REDEREF implements reflective learning by analyzing execution history post-task. The reflection process:
\begin{enumerate}
    \item Records successful tool sequences and outcomes
    \item Identifies failure patterns
    \item Updates ToolTree value estimates
    \item Refines safety policy based on false positives/negatives
    \item Adjusts budget estimates based on actual costs
\end{enumerate}

\subsection{CLI Commands}

AgentOS provides the following commands:

\begin{verbatim}
# Run task with auto mode
agentos run "Build a REST API for todo list"

# Interactive wizard mode
agentos wizard

# Session management
agentos sessions
agentos resume --session <id>
agentos delete --session <id>

# Configuration
agentos config set model gpt-4
agentos config set budget 5.00

# Safety bypass (trusted environments)
agentos run "task" --auto-confirm
\end{verbatim}

\subsection{MCP Integration}

AgentOS implements the Model Context Protocol \citep{hou2025mcp} for extensible tool integration:

\begin{verbatim}
from agentos.tools.mcp import MCPClient

client = MCPClient("http://localhost:8080")
tools = await client.discover_tools()
# Tools automatically integrated into HTAA registry
\end{verbatim}

MCP security is handled through MCPShield-style trust calibration \citep{mcpshield2026}, which validates tool descriptions and restricts dangerous operations.

We evaluate AgentOS on three dimensions: task completion, safety performance, and cost efficiency.

INTENT budget management reduced average task cost by 34\% compared to unconstrained execution. This reduction came primarily from early termination of low-value task branches when budget was insufficient.

% 6. Conclusion and Future Work
\section{Conclusion}

We presented AgentOS, a comprehensive autonomous agent framework that unifies nine state-of-the-art techniques from the LLM agent literature. Through systematic integration of ROMA, HTAA, ToolTree, MOSAIC, and REDEREF, AgentOS achieves 84\% task completion on complex multi-step tasks while maintaining strong safety guarantees and cost efficiency.

Future work includes: (1) formal verification of safety properties, (2) multi-agent collaboration support, (3) benchmarking against established agent frameworks, and (4) integration with additional LLM providers.

% Broader Impact Statement
\section*{Broader Impact Statement}

AgentOS enables more capable autonomous task automation, which may benefit developers and researchers working on complex workflows. Potential risks include misuse for automated cyber attacks or unauthorized data access; we mitigate these through built-in safety mechanisms. Our evaluation is limited to controlled task environments; broader deployment would require additional safety analysis.
